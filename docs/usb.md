# The inglenook USB stick (a persistent system to try)

`images/usb.sh` builds `build/usb/inglenook.img`, a raw disk image of the current tree that boots
the **whole OS from a USB stick** on a physical UEFI machine, with `/etc` and `/var` kept on the
stick. It is for trying the system on a machine. It is not the installer: to install Inglenook onto
a disk, use the installer stick ([installer.md](installer.md)).

```sh
images/usb.sh                       # ~10 min; prints the login details at the end
lsblk                               # find the stick, e.g. /dev/sdX — double check!
sudo dd if=build/usb/inglenook.img of=/dev/sdX bs=4M conv=fsync status=progress
```

`build/usb/inglenook.img.zst` is the same image compressed. The image is 14 GB by default
(`TARGET_SIZE=...` to change); the stick must be at least that large. It is not encrypted and has no
separate `/var`: it travels between machines, so no TPM key could follow it.

## Before booting

- **Turn Secure Boot off** in the firmware setup. The loader (systemd-boot) and the UKI are unsigned.
- Boot from the stick through the firmware's one-time boot menu (usually F12 or F8/F10/Esc). The loader
  sits on the removable-media path `\EFI\BOOT\BOOTX64.EFI`, so any UEFI machine finds it.
- The machine needs the wired network only for ssh (DHCP). There is no GUI yet: you get a text console.

## Logging in

The console password is generated by `usb.sh` into `build/usb/` and the ssh key is `dev-keys/` (both
gitignored); nothing secret is in the repository. The key is an unprotected test key, not for real use.

| What | Where |
| --- | --- |
| console login | user `user`, password in `build/usb/password` |
| ssh | `ssh -i dev-keys/id_ed25519 user@inglenook.local` (copy that private key to your workstation), or `user@<ip>`; the console login screen shows the IPv4/IPv6 addresses (press Enter to refresh them) |

The password is a systemd credential on the stick's EFI partition
(`\loader\credentials\passwd.hashed-password.user.cred`) that `systemd-sysusers` applies when it
creates `user`. The ssh public key is baked into the image at `/usr/lib/ssh/authorized_keys/user`.
To use your own key, put it in `dev-keys/authorized_keys` (and delete `build/usb/password` for a new
password) and rerun `images/usb.sh`, or add credentials to the mounted EFI partition:

```sh
echo -n "$(openssl passwd -6)" | systemd-creds encrypt --with-key=null \
    --name=passwd.hashed-password.user - passwd.hashed-password.user.cred
# copy it to <ESP>/loader/credentials/
```

There is no `sudo` and no setuid file: over ssh, `run0` asks for the `user` password through polkit
(a tty is needed: `ssh -t`).

## What was verified (in QEMU, not on hardware)

ssh key login; console/ssh password login from the ESP credential; rootless podman pulling and running
an image; `pcscd` reachable over ssh with a virtual CCID reader (so `ykman`, `yubico-piv-tool` and
OpenSC can talk to it; wheel members are allowed by a polkit rule); hostname `inglenook`. On hardware
this stick booted to the login prompt.

Not testable here: a real YubiKey, the Intel iGPU/NIC drivers, your firmware's boot menu.

## What to try

- `podman run --rm -it registry.fedoraproject.org/fedora echo hi` (rootless podman; `buildah`, `skopeo`
  and `git` are installed too).
- A YubiKey: `ykman info`, `ykman piv info` (`pcscd` starts on demand through its socket),
  `ssh-keygen -D /usr/lib64/pkcs11/opensc-pkcs11.so` for PIV keys. If `ykman` cannot see the key, note the
  output of `lsusb`, `opensc-tool -l` and `journalctl -b | grep -i -E 'pcsc|yubi|udev|avc'`.

## Known limits

- **SELinux is permissive** on purpose, and the policy is built without `dontaudit` rules, so
  `ausearch -m avc` as root after booting lists every denial the strict policy would have caused: that
  is the list to bring back. (Or use `enforcing=1` in a rebuilt UKI: `SELINUX_ENFORCING=1 images/usb.sh`.)
- Secure Boot unsigned; no TPM binding; no disk encryption.
- No GUI, no sound, no wifi tooling beyond what the base ships.
- If `/etc` and `/var` are wiped, the initrd restores `/etc` from its factory copy and labels it; the
  system comes back by itself (`images/test/wipe.sh`).
