# AGENTS.md — Inglenook Bootc Image Agent Configuration

> **Status: early but working.** The image builds (`images/build.sh`) and boots in
> QEMU with the composefs backend, systemd-boot and a UKI (no GRUB, no dracut),
> SELinux permissive (while the policy is worked out), a clean journal and a
> wipe-able `/etc` and `/var`;
> `images/installer/stick.sh` makes the installer stick (docs/installer.md): a root shell in
> the initrd, `inglenook-install` installs the image to the internal drive. A Sway desktop and
> its tools are in the image packages; the default target is graphical.target and sddm
> (enabled by its preset) shows the login screen.
> Update this file as things change.

## Project Overview

**inglenook** — a Fedora-based bootable OS image built with [bootc](https://github.com/containers/bootc) (bootable containers), from the [Snugmo](https://github.com/snugmo) GitHub org. The image is defined by a `Containerfile` that FROMs the official Fedora bootc base, built into an OCI image with `podman`/`buildah` (the base's bootc stage is inherited), and is installed on a host with `bootc install` from a running container; deployed hosts update transactionally via `bootc upgrade`.

## Structure

Layout:

```
images/
  Containerfile  # The OS image: Fedora base + packages + host configuration
  build.sh       # buildah wrapper: pre -> mkosi initrd -> base -> composefs digest -> UKI image
  initrd/        # mkosi config for the initrd (replaces dracut): mkosi.conf + mkosi.extra/
  rootfs/        # Files copied into the image as-is (units, drop-ins, issue banner)
  installer/     # The installer stick: UKI addon (tools + inglenook-install under /usr/installer), stick.sh, mkosi.conf of its packages; see docs/installer.md
  addons/        # UKI addons for per-machine boot tuning (serial-console.sh: console=ttyS0)
  test/          # Rootless QEMU/KVM tests: vm.sh (harness), smoke.sh, wipe.sh, xfsvar.sh; work dirs under build/
docs/            # On-demand reference docs — read when relevant (see below)
```

## Key Conventions

### Commit Conventions

- Small commits, one per meaningful change, committed as you go.
- Subject: `<emoji> <type>: <summary>` — a conventional type prefix
  (`feat:`, `fix:`, `chore:`, `docs:`, …) and a summary under 72 chars.
  The single emoji is chosen per change to capture what actually changed;
  there is no fixed set of allowed emojis.
- End the message with an `Assisted-by: <agent>:<model>` trailer (no
  "generated with" line).

### OS Image (`Containerfile`)

- Based on **Fedora 45** via `registry.fedoraproject.org/fedora-bootc:45` (a single `FEDORA_VERSION` build arg drives the `FROM` and the base.name label; F45 is the target because its release is due within weeks, so working out issues on F44 would mean redoing or discarding fixes at the rebase; we stay off Rawhide/46 so unfinished upstream work doesn't mask our own tooling issues; expect F45 prerelease quirks to change at release, so re-check workarounds then, e.g. the SELinux denial on `ssh.ephemeral-authorized_keys-all`) — the earliest bootc-capable layer of the Fedora image cake (bootc-ified `fedora-minimal`, no desktop/GUI), not UBI; has no baked-in account (the first user is created by the installer).
- The final stage must be a bootc stage — our base already is, and the stage is inherited through added layers. Never base a stage on a *non*-bootc image without adding a `switch-to-bootc-container` step.
- All binary downloads are verified as far as possible (SHA-256 `ADD --checksum=…`, cosign signatures, or SLSA provenance).
- Order instructions least-to-most frequently changing; package installs before configuration, to maximize layer reuse.

### Build Script (`images/build.sh`)

- Uses `buildah` (not `docker`) — rootless, works in CI without a Docker daemon (the bootc base image needs no special build tooling; the bootc stage is inherited through the build).
- The tag is the git-describe version (`git describe --tags --always --dirty`, leading `v` stripped, falls back to `latest`), so the image ref is `ghcr.io/snugmo/inglenook:<tag>` — e.g. `0.1.0`.
- Registry defaults to `ghcr.io/snugmo`; `./images/build.sh push` publishes to GitHub Container Registry. For local dev / CI use `DEV_REGISTRY=localhost:5000`.
- Passes `--build-arg VERSION=<tag>` and `--build-arg REVISION=$(git rev-parse HEAD)` for the `org.opencontainers.image.*` labels in the Containerfile (same convention as cote).
- The UKI's PCR 11 prediction is signed (`.pcrsig`, `.pcrpkey`) with a test key `dev-keys/pcr-{private,public}.pem` that `build.sh` makes with `ukify genkey` when missing (`PCR_PRIVATE_KEY`/`PCR_PUBLIC_KEY` override; gitignored, never commit). The private key reaches the UKI stage only as the build secret `pcrkey`; the public key is the UKI's `.pcrpkey`, which systemd-stub's tmpfiles rule copies to `/run/systemd/tpm2-pcr-public-key.pem`, where systemd 262 `systemd-tpm2-setup` looks for it to create the NvPCRs. **Do not install it under `/usr/lib/systemd` or `/etc/systemd`**: `systemd-cryptenroll` (bootc's `--block-setup tpm2-luks`) then binds the key to the signed PCR 11 and needs the signature to open the device, which the installer VM (no UKI) does not have ("Failed to load PCR signature"). The same key is in `/run/systemd` inside the booted UKI's initrd, where `systemd-repart` would bind the new `/var` (and the installer's root) to the signed PCR 11 too, and the unmeasured test VM then cannot unlock it on the next boot: `inglenook-var-repart.service` and the installer pass `--tpm2-public-key-pcrs=` (empty; `--tpm2-public-key=` does not turn it off in repart, although it does in `systemd-cryptenroll`) to keep the TPM keys PCR-less until the PCR policy is designed (without it `systemd-tpm2-setup-early` and the `systemd-pcrproduct`/`pcrlogin@` units fail with ENOENT on a measured boot; the test VM is not measured, so only real hardware shows it). The UKI must also be built with `ukify --sign-initrd-pcrs`: systemd 262 creates the NvPCRs with a write policy that only a signature bound to the `enter-initrd` phase with the policy reference `initrd` satisfies, and without that extra signature every NvPCR initialisation fails with `Couldn't find signature for this PCR bank, PCR index and public key` (surfacing as `Device not a stream`; the `NV_DefineSpace` `0x14c` lines (`TPM_RC_NV_DEFINED`) next to it are the harmless "index exists, reuse it" path, so a TPM clear is not needed). A key per release, kept outside the repo, is still to be decided.
- Environment: `SSH_PUBKEY` (baked-in login key), `KARGS` (UKI kernel command line), `FEDORA_VERSION`, `DEV_REGISTRY`. The pipeline is `pre` target → mkosi initrd → `base` target → composefs digest → final image with the UKI (see Gotchas 6-8).

## Gotchas

1. **The bootc stage is mandatory**: `bootc install` only works on images with a bootc stage (the `containers.bootc` label + bootc tooling, i.e. an ostree commit as the base layer). Our base is bootc-ified and the stage persists through added layers — but don't base a stage on a non-bootc image without a `switch-to-bootc-container` step, and never override the bootc labels.
2. **Image pull access**: `bootc install` — and host-side `bootc upgrade`/`switch` — pull the image from a registry; the machine running them must have credentials for the registry.
3. **No baked-in account.** The image has no regular account (the old `user`, UID 1000 shared with the cote workspace images, is gone), no ssh key and no sudo. The first user is a systemd-homed account made from the installer's credential (gotcha 24); homed UIDs are in the 60001-60513 range. Host volume mounts must be writable by that user.
4. **Update, don't reinstall**: deployed hosts are updated with `bootc upgrade` (or `bootc switch` to change image). Re-running `bootc install` on an already-installed host is not the update path.
5. **Layer caching**: the bootc stage must stay last; do not reorder instructions above it without understanding the stage architecture.

6a. **Stale `pre` layers = wrong initrd modules.** The initrd's kernel modules come from the `pre` target, the UKI's kernel from the final image. After `fedora-bootc:45` moved to a newer kernel a cached `pre` still had the old one (kernel 7.2.11 booting with 7.2.9 modules: no `usb_storage`/`sd_mod`, the installer saw no stick; virtio is built in, so a plain VM boot hid it). Symptom: `ls /usr/lib/modules` in the initrd lists two versions. Fix: remove the `localhost/inglenook-*` images and `podman image prune -a`, rebuild.
6b. **Plymouth** is in the image (`plymouth`, `plymouth-system-theme`: with it come the two-step and label plugins and the Cantarell font the prompt text needs) and in the initrd (mkosi's `plymouth` profile in `images/initrd/mkosi.conf`). `systemd-ask-password-plymouth.path` (shipped by the plymouth package) forwards every password/PIN question to it, so no extra glue is needed. The kernel command line has no `splash`/`quiet`, so it shows the text mode with the boot messages; add `splash` (and `quiet`) to `KARGS` for the graphical splash. Untested on the machine; its SELinux denials, if any, are not yet in the policy.

6c. **wlsctx** (github.com/wlsctx/wlsctx) has no releases and its ghcr image is not public, so the `wlsctx-build` stage at the top of the Containerfile builds the binary with cargo from a commit pinned by tarball SHA-256 (`--locked`); only `/usr/bin/wlsctx` goes into the image. Its quadlets, user units and SELinux blocks are not installed; they are per-user and need the pod images.

6. **No dracut**: the initrd is built by mkosi (`images/initrd`) from the `pre` stage's kernel modules and bootc's `initramfs-setup`/`bootc-root-setup.service`, and installed as `/usr/lib/modules/<kver>/initramfs.img` in the `base` stage. Anything the initrd needs (modules, units) is mkosi config, not a dracut module. The initrd is part of the composefs digest, so it must be in place before the digest is computed.
7. **The UKI embeds the image digest**: the UKI's `composefs=<digest>` must equal the composefs digest of the finished rootfs, so `build.sh` builds the `base` target, computes the digest with `bootc container compute-composefs-digest-from-storage`, then builds the final image with `COMPOSEFS_DIGEST`. Do not use `bootc container ukify --rootfs` in the Containerfile — it measures a mount whose directory mtimes are the layer-extraction time, which never matches what `bootc install` computes. `/boot` is excluded from the digest, so the UKI itself can be added last. Build with layer caching (`--layers`): a rebuilt base has different contents and a different digest; `build.sh` fails if the final image's digest differs.
8. **`rw` on the UKI command line**: without it `/sysroot` mounts read-only and the `/var` and `/etc` binds inherit that, so `/var` is read-only and services fail.

9. **No loop devices / root in the dev container**: `bootc install` therefore runs inside a throwaway installer VM (`images/test/vm.sh install`), not on the host. Never debug a stale image: `vm.sh` passes the image ref through the 9p share, and the installer removes the old tag before loading.
10. **Login and SSH**: the tests log in as **root** over ssh with `$WORK/key` (`vm.sh` hands its public half to the VM in the `ssh.authorized_keys.root` SMBIOS credential; `SSH_USER=` selects another account); nothing is baked into the image. ssh-over-vsock's per-connection sshd only reads `ssh.ephemeral-authorized_keys-all` plus `~/.ssh/authorized_keys`, and on Fedora 45 prerelease SELinux denies sshd-session reading that credential for non-root users, so the credential route works for root only. Homed users carry their ssh keys in the record (`sshAuthorizedKeys`; sshd asks `userdbctl`, see docs/tokens.md).

11. **Factory /etc**: the last `pre` step snapshots the finished `/etc` into `/usr/share/factory/etc` and generates `/usr/lib/tmpfiles.d/inglenook-etc-factory.conf` (`C! /etc/<entry>` per top-level entry; `machine-id`, `hostname`, `credstore*` and the `-` backup copies are excluded on purpose). If `/etc` is wiped, `inglenook-etc-restore.service` in the initrd restores all of it before switch-root and labels it, because PID 1 loads the SELinux policy from `/etc/selinux` and early services (udev, hwdb) read `/etc` before tmpfiles in the real root has run. **Labeling in the initrd** (no policy loaded in the kernel yet) uses `setfiles -m -F -r /sysroot -c <policy.NN in the target> <file_contexts in the target> /sysroot/etc`: `-r` strips the prefix so the path-based patterns match as `/etc/...`, `-c` validates against the policy file in the target tree, and `-m` is essential: without it setfiles reads /proc/mounts and silently skips mounts that do not show `seclabel` yet, which made a plain `setfiles` a no-op (files stayed labeled `kernel`). With it the first boot after a wipe is clean. Anything added to `/etc` in the Containerfile must come before the factory snapshot step. Test with `images/test/wipe.sh`. `passwd` and `group` are in the factory set (system accounts are in `/usr/lib/{passwd,group}` via nss-altfiles; `wheel` has to stay in `/etc/group` so that accounts can be members); `shadow` and `gshadow` are not (the policy silently denies tmpfiles getattr on them, so a rule logs an error every boot).
12. **Units with `DefaultDependencies=no` race tmpfiles on a fresh `/var`** (e.g. `rpc-statd-notify`): add `After=systemd-tmpfiles-setup.service` in a drop-in under `rootfs/`. The wipe and smoke tests fail on any `journalctl -p err` line except the VM's TDX probe, so such races show up.
13. **Never kill the test VM**: `vm.sh stop` powers it down over QMP; killing qemu loses recent writes (ext4 delayed allocation leaves zero-length files, which once looked like a broken factory copy).
14. **Debugging without a root login**: `VM_EXTRA_UNIT=file.service vm.sh start` injects a unit via SMBIOS credentials; remember systemd expands `%` in `ExecStart` (write `%%`) and `$`-less shell is easier.
15. **Rootless podman/buildah** need `/etc/subuid` and `/etc/subgid` entries and a homed account gets none by itself, so `inglenook-install` appends `<user>:524288:65536` to both in the new system's `/etc` (and labels them). The image seeds nothing.

16. **Encrypted everything, XFS /var (the default of an installed system).** The root is LUKS2 sealed to the TPM by `bootc install --block-setup tpm2-luks` (docs/installer.md; ext4 inside, because composefs needs fs-verity and `mkfs.xfs` has none; bootc also adds an empty unencrypted `boot` partition; only the ESP is plain). `inglenook.var=xfs` is in the image's default kernel command line (which has no `console=`: on a machine without a UART `console=ttyS0` makes the getty generator start a `serial-getty@ttyS0` that fails and restarts every 10 s, since the 8250 driver always has a ttyS0 node with a `device` link; a serial console is the addon of `images/addons/serial-console.sh` in `\loader\addons\` of the ESP, and `vm.sh start` passes `console=` for the tests) (`KARGS` in the Containerfile): in the initrd, `inglenook-var-repart.service` runs `systemd-repart` (definition in `/usr/lib/inglenook/repart.d`, deliberately *not* `/usr/lib/repart.d`: files there make the stock `systemd-repart.service` run in the initrd and fail) before bootc sets up the root, creating a LUKS2 partition (`Encrypt=tpm2`, type `var`, label `var`) with XFS in all free space after the root, including space past the image end on a bigger disk. `inglenook-var-mount.service` runs `/usr/lib/inglenook/var-mount`: it attaches the volume with `systemd-cryptsetup` (TPM token) and mounts it over the ext4 `/var` bind that `bootc-root-setup` makes at `/sysroot/var`, with `rootcontext=var_t` (a fresh XFS root is unlabeled). It is a *service*, not a `sysroot-var.mount` unit: systemd skips a mount unit for a path that is already mounted. Without free space after the root, `/var` stays on the root (repart fails, logged, not fatal); without a TPM the repart service is skipped by `ConditionPathExists=/dev/tpmrm0` and `/var` stays on the root too. Both initrd services are ordered `After=tpm2.target` (no `Wants=`: systemd-tpm2-generator hooks the target in only when firmware reports a TPM whose device is not there yet, so it waits for a slow driver and is a no-op without a TPM). Do not use `systemd-tpm2-setup-early`'s SRK file or `systemd-analyze has-tpm2` as the "is there a TPM" test: both need a measured boot, which the test VM's OVMF does not give, so they say no/partial there although the TPM works. The base image's `bootc-generic-growpart.service` (grows a plain root partition to the end of the disk, VM only, skipped for LUKS) is masked in the Containerfile: with a plain root in a VM it ate the space meant for `/var`. On the first boot after the install systemd 262's `systemd-cryptenroll-firstboot.service` asks on the console for a recovery key / passphrase / FIDO2 token for `/var` (empty skips; the tests skip it with `systemd.firstboot=no`, passed through systemd-stub's SMBIOS string by `vm.sh`). The TPM keys have no PCR policy yet (bootc's cryptenroll uses none, and the VM's OVMF does not measure). bootc state stays on the ext4 root. Early units that create directories in `/var` themselves race tmpfiles on the empty filesystem and get denied: order them after `systemd-tmpfiles-setup.service` (done for `rpc-statd-notify` and `systemd-random-seed`). **Test harness:** `vm.sh` attaches a software TPM (swtpm, `images/test/tpm-setup.sh` fetches it into `build/swtpm`) and installs with `--block-setup tpm2-luks --root-size 8G` by default (`TPM=0`, `BLOCK_SETUP=direct`, `ROOT_SIZE=` opt out). Start the VM with the same `TPM` setting as the install (the key is sealed to that TPM's state, in `$WORK/tpm`), and note the installer VM boots under OVMF as well (PCR 7 must match). `vm.sh debug <script>` runs a script as root in the installer VM against the existing disk and TPM, useful when the initrd fails to unlock (the emergency shell has a locked root).

**Revisit: an XFS root.** The root is ext4 because composefs wants fs-verity and neither the kernel nor `mkfs.xfs` (7.1.1) offers it on XFS. fs-verity for XFS is on its way upstream (Andrey Albershteyn's v17 series, posted 2026-10-02; the core fsverity patches are in the 7.4 fsverity tree, the XFS ones target 7.5, with a read-only-compatible on-disk feature flag; thread: https://ratatoskr.run/linux-fsdevel/2026/10/17694139). Check back when the image's kernel is 7.5 or later: does `mkfs.xfs` have a verity option, and does `bootc install --filesystem xfs` with the composefs backend enable it (bootc passes `-O verity` for ext4 today)? Until then do not use `--allow-missing-verity`, it drops the integrity check.

17. **SELinux is permissive on purpose**: the UKI carries `enforcing=0` (`SELINUX_ENFORCING=0`). `SELINUX_ENFORCING=1` does **not boot yet**: the mkosi initrd has no policy, and its systemd freezes with "Failed to load SELinux policy" when `enforcing=1` is on the command line (dracut would have put the policy there). Shipping the policy in the initrd is the long-term plan, not started. The stock `dontaudit` rules are kept, so the audit log has no siginh/rlimitinh/noatsecure spam (those are harmless and must not be allowed). Building with `SELINUX_NO_DONTAUDIT=1` runs `semodule -DB` and logs every denial the strict policy would produce, including those a `dontaudit` rule hides (no kernel switch for that; it is compiled into the policy): use it when hunting for missing rules, not for normal builds. Local policy is CIL (`images/rootfs/usr/share/inglenook/selinux/*.cil`, installed with `semodule -n -i` at build; no compiler needed). To find the rules a domain needs: boot, `ausearch -m avc` as root (or `vm.sh avc`), add `(allow ...)` lines. The tests fail only on denials missing from `images/test/selinux-denials.baseline`: the baseline is the to-do list, shrink it as rules or upstream fixes land. Process-transition perms (siginh, rlimitinh, noatsecure) are ignored as dontaudit noise (only seen in `SELINUX_NO_DONTAUDIT=1` builds). The one rule so far lets `sshd_session_t` read the `ssh.ephemeral-authorized_keys-all` credential (`init_var_run_t`), which works for root only: the credential directory is root-only and sshd reads authorized_keys as the target user.
18. **No dev key in the image.** `build.sh` used to bake `dev-keys/authorized_keys` into every image it built, `push` included; that is gone, and so is the persistent stick (`usb.sh`) that used to generate `dev-keys/` (gitignored; never commit a key). Logins come from credentials passed to the VM or from the installer.
19. *(Removed with the live stick; the install flow is gotcha 23 and docs/installer.md.)*
20. **Wrong or missing labels on the mutable state** (copied-over or restored files; the OS content itself is labeled inside the composefs image): the mutable parts are `/etc`, `/var` and the backing directories under `/sysroot/state` on the root filesystem, which carry ordinary xattr labels. Symptom: AVCs with `unlabeled_t` targets, or with `trawcon="kernel"` for files written before a policy was loaded. Recovery: boot permissive (the UKI default), then `sudo restorecon -R /etc /var` (the mounted views only). **Never run restorecon (or an autorelabel) on `/sysroot` or anything under it.** restorecon takes the label from the *path* of each file, and the file-context patterns describe the running system (`/usr`, `/etc`, `/var`, …); run on `/sysroot/state/...` or the object store the paths match nothing meaningful, so most files get a generic fallback label and the system breaks until a correct full relabel. The content-addressed object store is the worst case: its names are digests, so no pattern could ever be right (on ostree it also wrecks the hardlinked targets). The same reason is why `restorecon -R /etc /var` is fine: it is run on the paths as the running system sees them, never on their backing directories under `/sysroot/state`, and the initrd's `setfiles -r /sysroot ... /sysroot/etc` does the same (the prefix is stripped, so the patterns see `/etc/...`). This rules out `touch /.autorelabel` (a full relabel) and `restorecon -R /sysroot/state`.
21. *(Removed with the live stick.)*
22. **No setuid files**: the Containerfile strips the setuid bit from everything in `/usr` (sudo, GRUB, shim and bootupd are removed too) and `smoke.sh` fails on any setuid file. Privilege escalation is `run0` (polkit authorizes, wheel is admin). The password agent needs `polkit-agent-helper.socket` enabled: without it the agent execs `polkit-agent-helper-1`, which refuses to run unless setuid. File capabilities (`newuidmap`, `newgidmap`, `arping`) are kept for rootless podman. `run0` needs a tty to ask for the password (`ssh -t`) and the account needs a password (a homed user has the one from the installer).

23. **Token logins** (docs/tokens.md): authselect has `with-systemd-homed` (set in the Containerfile, so `pam_systemd_home` is in `system-auth`), `pam-u2f` is installed but `with-pam-u2f` is off, and `sshd_config.d/20-systemd-homed.conf` reads keys from homed records. **FIDO2 on homed records**: `homectl update --fido2-device=` (and `homectl create --fido2-device=` without `--storage=`) fails with "Object field 'perMachine' has wrong type null, expected array" (systemd issue 39599) when the record has no `perMachine` array: the installer's credential therefore carries `perMachine: []`, and a record made without it needs `--storage=directory` on the update (which writes the entry). `DefaultStorage=` in homed.conf does *not* help. Never add `AuthenticationMethods publickey,password` to sshd (locks out root and token-only users). A homed user's ssh login needs the token in the *server*. `images/test/token.sh` drives `softfido.py`, a small software CTAP2 authenticator over uhid; it checks the wiring, not real YubiKeys. Pitfalls: `homectl create` always asks for a password (remove it afterwards with `images/test/token/nopw.sh`), `$PIN` is ignored (answer the ask-password queue), and `pkill -f` matches your own ssh command line.

23. **The installer (docs/installer.md)** runs in the initrd of the stick's own UKI, selected by the addon's `rd.systemd.unit=`. It is `bootc install to-filesystem` without a container: `--source-imgref oci:<dir>` skips bootc's container check, and `/etc/ostree/prepare-root.conf` must exist (the script copies the image's own from the stick; `/usr` is read-only there). The archive is extracted to a scratch partition on the target disk, never RAM; the stick is unmounted right after and can be pulled. Test commands go to an *interactive* bash over the serial console, so `!!` expands as history: never print or grep `!!!`. `systemd-repart` makes the root (`SYSTEMD_REPART_MKFS_OPTIONS_EXT4='-O verity'`, `Encrypt=tpm2`); do not seal TPM keys to PCR 12 (the addon changes it). `bootc-generic-growpart.service` of the base image is masked (it grew a plain root in VMs only). Do not put a TPM-presence test on `systemd-tpm2-setup-early`'s SRK file or `systemd-analyze has-tpm2`: the test VM's boot is not measured, so both say no/partial while the TPM works; use `/dev/tpmrm0` after `After=tpm2.target`. The scratch partition is removed with `sfdisk --delete`, **not** `sgdisk -d ... -q`: gptfdisk 1.0.10's `sgdisk -d N -q` silently skips the deletion (exit 0, nothing written), which once left the 6G scratch on the installed disk and gave /var half its space. The installed system has **no `/boot` mount and no `/etc/fstab`**: in this layout the ESP *is* the boot partition (bootc never persists a boot mount for `to-filesystem`), and bootc finds the ESP by device scan (`find_first_colocated_esp` from the root device) at install, upgrade and switch, so nothing needs it mounted; tools that want the boot files must mount `/dev/disk/by-partlabel/ESP` themselves.

24. **The first user.** Root is locked, so `inglenook-install` writes a `home.create.<name>` credential (a homed JSON record with `memberOf: [wheel]`, the password hash and the plain password in `secret`: homed refuses to create a home from a hash alone) into the deployment's `/etc/credstore` and labels it with `setfiles -r <deployment>`. `systemd-homed-firstboot.service` is enabled in the Containerfile; its drop-in adds `--member-of=wheel`, deletes `/etc/credstore/home.create.*` afterwards and replaces `ConditionFirstBoot=yes` by `ConditionDirectoryNotEmpty=!/var/lib/systemd/home`: the image ships `/etc/machine-id` as an *empty file*, which machine-id(5) rule 4 calls "not a first boot", so `ConditionFirstBoot` is never true in the real system (this also keeps `systemd-firstboot.service`, which would prompt for a root password, from ever running; shipping `uninitialized` instead would turn that on, and would make the initrd's cryptenroll wizard, which tests `ConditionFileNotEmpty=!/sysroot/etc/machine-id`, skip). `homectl firstboot` prompts on the console only when no regular user exists, which is now the case on an install without a first user: the wizard asks for one at the first boot (the account joins `wheel`). Without a credential it prompts on the console. `systemd.firstboot=no` (what `vm.sh` adds by default) also skips this wizard: tests that need it use `VM_FIRSTBOOT=1` and skip the disk-encryption wizard (it prompts on a console nobody answers) with `VM_CMDLINE=inglenook.cryptenroll=no`, a condition our drop-in adds to it in the initrd (`systemd.mask=` did not stop it there).

## Adding New Components

- **New package/tool**: add it to `images/Containerfile` (respecting layer-cache ordering), rebuild, and verify the bootc labels survived (e.g. `skopeo inspect --config ghcr.io/snugmo/inglenook:<tag> | jq .config.Labels`).
- **New media** (e.g. VM image, ISO): not part of the current bootc CLI — work out an osbuild-based flow first, then add it to `images/build.sh` rather than a second `Containerfile`.
